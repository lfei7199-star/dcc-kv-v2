## 2. ΔQ 的定义（冻结）

### 2.1 逐 prompt 得分

\[
S_{i,m}=100\cdot f_{d(i)}\big(q_{i,m}\big),\qquad i\in\text{dataset } d
\]
`q_{i,m}` 是第 `i` 条 prompt 在第 `m` 臂上的官方指标原始输出。

### 2.2 `f_d` 必须是恒等 ×100 —— 这条比「冻结一个线性区间」更强

你的裁定允许「非 [0,1] 指标在实验前固定线性归一化区间」。**我不建议用这个分支**，因为它会开一个隐性自由度。理由是算术的：

设 `f_d(q) = a_d·q + b_d`，则

\[
\Delta Q=\frac1D\sum_d\big(S_{d,M_1}-S_{d,M_2}\big)
=\frac1D\sum_d a_d\big(\bar q_{d,M_1}-\bar q_{d,M_2}\big)
\]

**截距 `b_d` 在差值里完全消掉；斜率 `a_d` 不会消，它变成了 dataset 的隐性权重。**

⇒ 「给某个 dataset 定一个归一化区间」= **给这个 dataset 加权**。只要 `a_d` 不全相等，`1/D` 的等权就是名义上的，实际是 `a_d` 加权。这正是你要求禁止的「混量纲」的另一种形态，而且更隐蔽——它在公式里看不出来。

所以冻结为：

| 规则 | 内容 |
|---|---|
| **R1** | `a_d ≡ 100`，`b_d ≡ 0`，对**所有** dataset 相同 |
| **R2** | 前提是官方指标的取值域本就是 `[0,1]`；运行时断言 `0 ≤ q ≤ 1` |
| **R3** | 越界一律 **FAIL**，不截断、不重标定、不替换指标 |
| **R4** | 若某 dataset 真的越界：走**修订**（amendment）补一条规则，且该修订必须对所有 dataset 同时生效（不得只调一个） |
| **R5** | 禁止任何基于本轮 A/B/B′/C 观测值的 min-max、z-score、分位归一化 |

LongBench 官方 six-metric 的取值域（需在跑第一条数据时实测确认一次）：

| 任务类 | 官方指标 | 值域 | `a_d` |
|---|---|---|---|
| 单文档 / 多文档 QA | `qa_f1_score`（token-F1）、EM | [0,1] | 100 |
| 摘要 | `rouge`（R-1/2/L 的 F） | [0,1] | 100 |
| few-shot 学习 | `classification_score`（Acc） | [0,1] | 100 |
| 合成任务 | `count_score` | [0,1] | 100 |
| 代码补全 | `code_sim_score`（EditSim） | [0,1] | 100 |
| 检索 | `retrieval_score` | [0,1] | 100 |

若确认全部落在 [0,1]，则**整个归一化环节没有任何自由参数**——这比「冻结一个区间」可审计得多：没有可调的旋钮。

> R2–R4 是我在你裁定基础上收紧的（你的分支是「定区间」，我建议改成「断言+修订」）。理由：定区间等于定权重。**这一处需要你确认**（§9-①）。

### 2.3 组装（D 通用）

\[
\Delta Q(M_1,M_2)=\frac1D\sum_{d=1}^{D}\Big(\bar S_{d,M_1}-\bar S_{d,M_2}\Big),
\qquad \bar S_{d,m}=\frac{1}{n_d}\sum_{i\in d}S_{i,m}
\]
- `D=1` 时退化为单个数据集的均值差（P2 情形）。
- 无论 `n_d` 是否相等，**dataset 之间等权**。
- 只做**同一 dataset 内**的差值——与你的裁定一致，`b_d` 消掉也印证了这一点。

### 2.4 单位，以及一条必须写进正文的可比性限制

单位：**normalized pp**（每个 dataset 归一到 0–100 后的等权平均点）。

**不可直接与文献数字相减**：`design/18` §4.2 引的 AM 读数（QASPER −2.8、LBv2 −6.3、QuALITY −1.0）是**单基准原始指标点**，不是 21-dataset 等权归一化点。它们只能约束 δ 的**量级**，不能作为 δ 的等号。
这条要写进 prereg 的说明栏，否则以后一定会有人把「AM 掉 2.8，我们 δ=2.5 更好」写进正文——那是两个不同的单位。

## 3. 你的 §1 与 §4 之间有一处不自洽，需要选一个

- 你的 §1：`ΔQ = (1/D)Σ_d` ⇒ **dataset 等权**，每条 prompt 的权重是 `1/(D·n_d)`。
- 你的 §4：「prompt-level paired bootstrap」⇒ 若按 prompt 均匀重采样，每条权重 `1/N`，是 **prompt 加权**。

`n_d` 不等时（P1 情形下必然不等），**这两个估计量不是同一个数**。用 prompt 重采样算出来的 CI，不是 `(1/D)Σ_d` 的 CI。

**唯一自洽的做法：分层（within-dataset）bootstrap** —— 在每个 dataset 内部有放回重采样 `n_d` 条，重算 `Δ_d`，再按 `1/D` 相加。这样重采样的估计量与 §2.3 的估计量**逐字相同**。

代价（必须写明）：`n_d≈9.5` 时，percentile CI 在尾部粗糙；`D=1`（P2）时分层与不分层无差别。

**建议**：主估计量 = dataset 等权（分层 bootstrap）；secondary = prompt 加权（并注明它不回答 §2.3 的估计量）。
**这一处需要你确认**（§9-②），因为它是你的两条裁定相撞的地方，不该由我替你选。

## 4. δ 的两个绑定（冻结）

### 4.1 两个判据

| | `δ_shared` | `δ_DCC` |
|---|---|---|
| 绑定 | `Δ_shared = B′−B` | `Δ_DCC = C−B′` |
| H0 | `Δ_shared ≤ −δ_shared` | `Δ_DCC ≤ −δ_DCC` |
| 判定式 | `CI_low(B′−B) > −δ_shared` | `CI_low(C−B′) > −δ_DCC` |
| 实质含义 | 压缩可接受的质量预算 | destination-conditioning 的不劣界 |
| 是否强制相等 | **否**（允许不同值，但必须各自给理由） | 同左 |
| 先验方向 | 负（AM 原文 −1.0 ~ −6.3 单基准点） | ≈0 或正 |

**记入 prereg 的一句**：两个 δ 不强制相等，故**不允许**在事后用其中一个的通过去补另一个的失败。

### 4.2 归因链（四行，独立报告）

```
A → B    : SP 是否正确、是否真正接管（结构性，不做质量 NI）
B → B′   : shared compression 的代价（δ_shared）
B′→ C    : DCC 的独立 destination-conditioning 增量（δ_DCC）★ 主判据
A → C    : DCC 整体相对 Dense 的最终系统结果（secondary，不作 NI 检验）
```

★ 这一行是本次裁定的核心：**DCC mechanism 的 NI 只由 `B′→C` 承担**。

### 4.3 A→C 的地位

`A→C` 混入了 `Δ_SP`（多卡接管本身的开销与收益），不能把差异归到 DCC。故：
- 只作 overall-system 描述性结果；
- **不得**用 `A→C` 做 DCC 的 non-inferiority 检验；
- 引用时必须同时给出 `Δ_SP` / `Δ_shared` / `Δ_DCC` 三段，禁止只报 `A→C`。

这条已写入 `design/11` §2（H4）与 §5.2。

## 5. Q13：检验方法（冻结）

### 5.1 判定式

\[
\boxed{\ \text{CI}_{\text{low}}\big(C-B'\big)>-\delta_{\text{DCC}}\ }
\qquad
\boxed{\ \text{CI}_{\text{low}}\big(B'-B\big)>-\delta_{\text{shared}}\ }
\]

95% CI，单侧判定的口径由上式给定（比较下界与 `−δ`）。

### 5.2 三条禁令

1. **不得**在看到正式数据后改用 t-test、Wilcoxon 或任何其它检验。功效不足不是换检验的理由——功效不足走 §7 的分支。
2. **不得**在总体结果出来后选择「更好看的那个」分层方式。task-stratified bootstrap 若要做，必须在 prereg 里作为**固定的第二层分析**登记。
3. **不得**因为 CI 跨过 `−δ` 就把结论写成「非劣」（那是「无法判定」），也不得写成「更优」（那是优势检验）。

## 6. Q10：等质量资源收益（口径冻结）

### 6.1 定义

\[
Gain_R=\frac{R_{B'}(Q^*)-R_C(Q^*)}{R_{B'}(Q^*)}
\]
- `Q*` **必须预先指定**，否则可以在曲线上挑一个差距最大的点。
- 建议 `Q* = Q_{B'}(t=1637)`：即共享压缩在**主预算**上的质量。理由：1637 是 Q4 冻结的主档，`Q*` 锚在这里，Q10 与 Q9 就共享同一个工作点。

### 6.2 三个候选 R，以及一个必须说破的事实

| R | 与 `t_C/t_B'` 的关系 | 方向 |
|---|---|---|
| 每 destination 稳态 compact KV bytes | `Gain_R ≡ 1 − t_C/t_{B'}`（**恒等**） | 正 |
| 通信 bytes（source→3 destination 合计） | 同上（两边都是 3 份 × t） | 正 |
| 构造期峰值显存（source 侧） | C 建 3 份 vs B′ 建 1 份 ⇒ **C 更差** | 负 |

⇒ **前两个 R 下，`Gain_R` 就是预算比的一个仿射变换，不引入任何新测量。**
⇒ 第三个 R 方向相反，若把它设为主资源量，Q10 会得出「C 更差」——那是真的，但不回答「等质量下更省」。

**建议**：主资源量 = 每 destination 稳态 compact KV bytes；通信 bytes 作 secondary；构造期峰值单列，作成本项报告，**不进 Q10 判据**。
**这一处需要你确认**（§9-④）。

### 6.3 四档分辨率边界（本轮新算出来的硬约束）

档位是 2× 间隔（819 / 1637 / 3274 / 6548）。要插值出 `t_C`，需要曲线斜率足够陡。先看斜率：

| 区间（AM 原文 5%→10%，即 +1637 token） | ΔQ |
|---|---|
| QASPER | +1.2 pp |
| QuALITY | +1.2 pp |
| LongBench v2 | +4.2 pp |

（由 AM 原文表格 5% 与 10% 两列相减：`0.428−0.416`、`71.3−70.1`、`70.2−66.0`。）

n=200 下 `ΔQ` 的 95% CI 半宽 ≈ `1.96·σ_d/√200`；σ_d=20 pp 时 ≈ **2.8 pp**。

⇒ **CI 半宽（≈2.8 pp）与一整个档位的质量变化（≈1–4 pp）同量级。**
⇒ `t_C` 的插值定位误差 ≈ 一个档位，**点估计不可用**。

结论：**Q10 只能出括号，不能出插值点。**

### 6.4 括号：`Q*=Q_{B'}(1637)` 下只剩一个可用端点

若主张 A 成立（C 同预算更优），则 `t_C < 1637` 必然。低于 1637 的档只有 819，故唯一可判的括号是：

\[
t_C\le 819\ \Longrightarrow\ Gain_R\ \ge\ 50\%
\]

这给 Q10 一个**极其干净的形式**——它等价于一次**跨预算非劣检验**：

\[
\boxed{\ \text{CI}_{\text{low}}\big(C@819-B'@1637\big)>-\delta_{Q10}\ }
\]

于是 `δ_Q10` 与 `δ_shared` / `δ_DCC` **同单位、同检验、同判定式**，三套判据合成一套。这是本轮最有用的一处结构简化。

其余可能：
- 若 `C@819` 不达 `Q*`，则 `Gain_R ∈ (0, 50%)`，**四档下不可分辨**，只能报「≥0 且 <50%」的上界。
- 若想让括号更细（75% / 87.5%），需把 `Q*` 锚到更高档位（如 `Q_{B'}(6548)`），但那是一条不同的主张，且需要更多档位授权。

**这一处需要你确认**（§9-⑤）：Q10 是否就按「单括号 + 跨预算 NI」冻结。

### 6.5 Q10 的工作长度：`L = 65 536`（2026-11-25 22:07 裁定）

| 项 | 内容 |
|---|---|
| L | **65 536**（配置上限，不是样本长度；实际输入 8 370–65 400，0/200 截断） |
| 为何不用 32 768 | 85/200 被截断（42.5%），比较会混入截断造成的任务变化 |
| 档位身份 | **新增档**，不在 R-d `criterion.lengths` 与 `design/11` §0.4 主工作负载内，须登记，不得伪装成既有冻结档 |
| 授权 | 819 档仍需**单独 GPU 授权**；选 L ≠ 授权 |

**一个必须一并登记的后果：同一档预算在两个长度上不是同一个压缩率。**
预算冻结的是绝对 token 数（每边 819/1637/3274/6548），分母是远端 key 数 `= L×3/4`：

| 每边 t | 三边合计 3t | L=130 944（远端 98 208） | **L=65 536（远端 49 152）** |
|---|---|---|---|
| 819 | 2 457 | 2.50% / 39.97× | **5.00% / 20.00×** |
| 1 637 | 4 911 | 5.00% / 19.99× | **9.99% / 10.01×** |
| 3 274 | 9 822 | 10.00% / 10.00× | **19.98% / 5.01×** |
| 6 548 | 19 644 | 20.00% / 5.00× | **39.97% / 2.50×** |

⇒ 在 65 536 上四档各「松一倍」。`Gain_R = 1 − t_C/t_{B′}` 不受影响（只含 t 之比），
但 **「5% / 20×」这个标签不能贴到 65 536 的 1637 上**（那里是 10% / 10×）。
⇒ 同时这也加强了一条 claim 边界：≤65K 的质量实验用的是**更温和的压缩**，
其结论既不能外推长度，也不能外推 130K 下的压缩强度。详见 `design/22` §5。

## 7. 两阶段 power 分支（规则冻结，数值不冻结）

```
Stage 1  pilot（2A 之后）
         测 σ_d(质量)：同臂两 seed 跑全部 n 条
         测 σ_d/μ(延迟)：2A 单次已含
Stage 2  计算 n_required(δ, σ_d) = (z_{1−α}+z_{1−β})²·(σ_d/δ)²
         分支 A：n_required ≤ n_available  → 做 NI 检验，报 §5.1 判定
         分支 B：n_required >  n_available  → 不做 NI 声称；
                                             只报 ΔQ 点估计 + 95% CI +
                                             「所需 n = ___」原文
```

**三条约束**：
1. 分支规则写进 prereg，**由数据触发，不得事后改分支**。
2. pilot 用的数据与检验用的数据**不重叠**（否则 `σ_d` 被数据污染）。
3. `n_available` 在 prereg 里写死（200，或 P2 情形下的实际值），不得因分支 B 的结果而改。

## 8. δ 数值推迟时的防污染规则（这是推迟的唯一代价）

你把 δ 的数值推迟是对的——`σ_d` 没有真值，就不该为了适配 n=200 去反推 δ。但推迟有一个风险必须用程序挡住：

**风险**：等 pilot 的 `σ_d` 出来之后再定 δ，很容易（即使无意识地）把 δ 定在「刚好让 n≤200」的位置。这与事后挑阈值是同一个病。

**防污染规则**（建议写进 prereg）：

| 步骤 | 内容 |
|---|---|
| 1 | 先落盘**理由文本**：δ 取自 `design/18` §5.4 的哪几条（R-a 文献分辨率 / R-c 实测退化上界 / R-d claim 力度），以及排除 R-b 的理由 |
| 2 | 理由文本落盘**之后**，才允许看 `σ_d` |
| 3 | δ 定稿时，若 `n_required` 与 200 相差在 20% 以内，须在记录里注明「δ 未按 n 调整」并附理由文本的哈希 |
| 4 | 若 δ 定稿后 `n_required > 200`，走 §7 分支 B，**不得回调 δ** |

这份文本就是「δ 不是 n 的函数」的唯一证据。没有它，推迟冻结算不上干净的预登记。

### 9.1 ⑤ 的附条件（裁定原文要求，机器可查）
