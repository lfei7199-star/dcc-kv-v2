## 2. Key Selection 一致性

**定义对照**：骨架旧规则聚合的是**原始缩放 logit** 的平方均值；AM 聚合的是**softmax 之后**的权重。两者只在「所有 query 的 softmax 分母相同」时单调等价，实际不成立。

**测试**

| 测试 | 断言 |
|---|---|
| `test_softmax_rms_matches_manual_definition` | 按 §3.3 手算 `s_j=sqrt(mean_i a_ij²)` 的排序结果，与 `select_keys` 逐索引相等 |
| `test_the_two_selectors_actually_disagree` | 旧/新规则在紧预算下选出的集合不同（否则升级无法被检验） |
| `test_unknown_selector_rejected` | 未实现的 selector 直接报错，不静默回退 |

**重合度实测**（`tools/diag_am_fidelity.py`，T=300，3 seed）

| 预算 | Jaccard（旧 vs 新） |
|---|---|
| 40× | 0.11 – 0.25 |
| **20×（主预算）** | **0.29 – 0.54** |
| 10× | 0.51 – 0.63 |
| 5× | 0.65 – 0.74 |

⇒ 主预算下近一半保留集不同。这不是参数级别的差异，是换了选择规则。

## 3. β 盒约束（U2）

**实现语义**（严格按 C.2，**不是** NNLS 后裁剪）：

1. `w⁰ = argmin‖Aw−m‖²`（Householder QR，无正则）
2. `w⁰ ← clip(w⁰, e⁻³, e³)`  ← warm start
3. 两步投影梯度：`w ← clip(w − η·Aᵀ(Aw−m), e⁻³, e³)`，`η = 1/‖A‖₂²`（幂迭代估）

`test_iters_zero_is_clamped_unconstrained_ls` 逐元素对照第 1–2 步的结果（差 < 1e-9），确认 warm start 是「无约束 LS + 裁剪」而非 NNLS 解。

**每档必须记录的字段**（U2 要求，全部由 `beta_box_ls` 返回）

| 字段 | 定义 |
|---|---|
| `bind_hi_count` / `bind_hi_frac` | `β_j ≥ +3 − 1e−6` 的 key 数 / 占比 |
| `bind_lo_count` / `bind_lo_frac` | `β_j ≤ −3 + 1e−6` 的键数 / 占比 |
| `dead_count` / `dead_frac` | **该 key 承担的块内重建质量 < 块总量的 1e−6**（与下界饱和是两件事，见下） |
| `mass_residual` | `‖Aw−m‖₂ / (‖m‖₂ + ε)`，与裁定给出的定义一致 |
| `beta_min/max/mean` | β 分布统计 |
| `beta_fit` | rank / sigma_min / sigma_max / cond / r_min / r_max |

**`beta_dead` 的语义已显式定义**（U2 要求不得含混）：盒约束下 `w_j` 恒 `≥ e⁻³ > 0`，所以「死」不能解释为 `w=0`。这里定义为**有效质量占比**：`contrib_j = w_j·Σ_i A_ij`，若 `contrib_j < 1e−6 · Σ contrib` 则该 key 在重建中实质无贡献。它与 `bind_lo`（下界饱和）是**两个独立量**，`test_dead_is_distinct_from_bind_lo` 保证两者都被报告。

**顶格率实测**（T=300，n_ref=2t，3 seed 均值）

| 预算 | `log(T/t)` | `bind_hi` | `beta_max` |
|---|---|---|---|
| 40× | 3.69 | **0.57** | 3.00 |
| **20×** | **3.00** | **0.16** | 3.00 |
| 10× | 2.30 | 0.00 | 2.96 |
| 5× | 1.61 | 0.00 | 2.88 |

主预算 20× 上 `log(T/t)=3.00` 恰在盒顶，16% 的 key 已顶格；40× 时升到 57%。这些数字只作**诊断**（合成），但说明盒约束在 20×/40× 是活跃约束，不是摆设。

## 4. OLS 与 rank 检查

**硬前置，不做静默兜底**

- `n_ref < t` → `RankDeficientError(stats={"reason":"n_lt_p"})`，在 `build()` 入口即拒
- 列秩不足 → `RankDeficientError(stats={...})`，QR 的 `min|R_ii|` 与容差一并带出
- **不存在**「加 λ 让它跑通」的路径：ridge 只在 `value_mode="ridge"` 这一显式消融臂上存在

**报告字段**：`rank` / `sigma_min` / `sigma_max` / `cond` / `tol` / `r_min` / `r_max` / `rank_deficient`。
其中 `sigma_min/max` 取 QR 的 `|R_ii|` 极值（真奇异值的下界估计），文档里已注明不是精确谱量——理由是把 Gram 拿去做 Jacobi 会把条件数平方，而且开销 O(p³)/sweep，在 t=80 时不可用。

**测试**

| 测试 | 内容 |
|---|---|
| `test_ols_fit_is_full_rank_and_finite` | 正常规模下 `rank == t`、`sigma_min > 0`、`v_sel` 全有限 |
| `test_ols_residual_not_worse_than_ridge` | OLS 的训练残差 ≤ ridge 残差 —— 若偷偷加了正则，这条必挂 |
| `test_duplicate_column_is_rejected` | 重复列 → 抛异常且带 stats（`r_min = 0`） |
| `test_n_lt_p_is_rejected_with_reason` | `reason == "n_lt_p"` |
| `test_build_rejects_n_ref_below_budget` | 构造链入口就拦，不等到求解 |
| `test_singular_stats_reports_condition` | 七个诊断字段齐备且 `sigma_max > 0` |

## 6. 统一标量 β 与逐 Key β 的数学区分

你指出的修正我接受并已写进模块：标量平移的性质只在**同块内统一平移**时成立，不能外推到逐 key β。

| # | 性质 | 测试 | 断言 |
|---|---|---|---|
| 1 | `softmax(z + c·1) = softmax(z)`：块内输出不变 | `test_property_1_uniform_shift_is_invisible_intra_block` | `c ∈ {−3,−0.5,1.7,3}` 下输出与无 β 相差 < 1e−12 |
| 1b | 但块的质量按 `e^c` 缩放 | `test_property_1b_uniform_shift_does_scale_block_mass` | 质量比 `= e^c`（1e−9） |
| 2 | 逐 key β **不会**被分母约掉，改变块内分布 | `test_property_2_per_key_beta_changes_the_distribution` | 单个 β 置 2.0，输出变化 > 1e−6 |
| 3 | 统一 β 在**拼接之后**才显形 | `test_property_3_uniform_beta_becomes_visible_after_merge` | 单块内不可见，拼接后变化 > 1e−9 |

这一组四条把「块级质量补偿」与「块内注意力分配」两种作用分开钉住，避免后续代码或论文把二者混谈。

## 8. 合成读数（advisory，不得进 Table 4）

**四臂对比**（T=300，n_ref=2t，3 seed 均值）

单块 rel-L2：

| 臂 | 40× | 20× | 10× | 5× |
|---|---|---|---|---|
| legacy(logitRMS, uniform, ridge) | 0.953 | 0.915 | 0.719 | **0.458** |
| +box β | 0.950 | 0.810 | 0.727 | 0.541 |
| +OLS value | 0.959 | 0.937 | 0.750 | 0.502 |
| **AM(softmaxRMS, box, OLS)** | **0.878** | **0.807** | **0.661** | 0.541 |

拼接级 rel-L2（追加 48 token 固定块，AM Eq.1+2）：

| 臂 | 40× | 20× | 10× | 5× |
|---|---|---|---|---|
| legacy | **0.895** | 0.805 | 0.630 | **0.403** |
| **AM** | 0.924 | **0.737** | **0.585** | 0.474 |

**结论必须如实写：合成数据不支持「AM 更优」。** AM 在 20×/10× 更好，在 40×/5× 更差。原因是合成世界的 key 是 iid 高斯，没有「某些保留 key 确实承担更多被删质量」的结构，逐 key β 拟合到的多是噪声。

**升级的正当性不来自这张表**，而来自：B′/C 若用非忠实实现与 AM 对照，方法定义就是错的。这一点与你的判断一致。

**一个真正有价值的合成读数**：`n_ref/t` 扫描（t=20，拼接级）

| n_ref/t | 1× | 2× | 4× | 8× |
|---|---|---|---|---|
| legacy | 0.824 | 0.630 | 0.549 | 0.534 |
| **AM** | **5.355** | 0.666 | 0.597 | 0.522 |

`n_ref = t` 时 AM 崩到 5.36（比 legacy 差 6.5 倍）——t 个参数只用 t 个样本拟合，设计矩阵近奇异。这条直接支撑 U3 取 2t 而非「够用就行」的算术下限。

**另一条反证**：`tools/measure_2c_specialization.py` 在**每档 n_ref=2t** 下测得 C 在 45 格中 42 格优于 B′，且 9/9 在大预算档也成立。但这是**预算与 n_ref 同步变化**的混合效应，不能归因给预算。这恰好说明未来四档 sweep 必须共用 `n_ref=13096`。

**实施过程中发现并修正的四处缺陷**（全部由测试暴露，记录下来备查）：

1. `_mass_system` 形参与调用方顺序不一致（`k` 与 `k_sel` 对调）→ 列数错误
2. Householder 更新把行索引与列索引混用 → QR 与正规方程解不一致
3. `_spectral_norm2` 写成 `at[j]·v` 而非 `Aᵀ(Av)` → 步长过小，投影梯度反而放大残差
4. `|R_ii|` 取反射后的对角元 → 舍入噪声掩盖秩亏，重复列检不出

修完后 QR 与正规方程在良态问题上差 **2.2e−16**，重复列的 `r_min` 为精确 0。
