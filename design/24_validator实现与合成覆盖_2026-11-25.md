## 2. `SE_cluster_w`：我改错一次，改回来的理由是「平移不变性」

### 2.1 四种可能的实现，目标参数各不相同

记 `m_c` 为簇 `c` 的行数（1 或 2），`ȳ_c` 为簇内 `d_i` 均值，`N = Σ m_c = 200`。
估计量永远是 `μ̂ = (1/200)Σ_i d_i`；分歧在**每个 replicate 怎么算**。

| # | 抽簇概率 | replicate | 目标参数 | 结论 |
|---|---|---|---|---|
| **A** | 均匀 `1/182` | `Σ m_c ȳ_c / Σ m_c`（Hájek 比值） | **200 行均值** | ✅ **采用** |
| B | 均匀 | `Σ m_c ȳ_c / 200`（分母固定） | 期望上也是 200 行均值 | ❌ **SE 依赖估计量的水平**，见 §2.2 |
| C | 均匀 | `(1/182)Σ ȳ_c`（簇等权） | `(1/182)Σȳ_c` | ❌ **换了目标参数**（§2.4 实测差 50%） |
| D | `π_c ∝ m_c` | `Σ m_c ȳ_c / Σ m_c` | `Σ m_c²ȳ_c / Σ m_c²` | ❌ 权重变 `m_c²`：`Σm²=236 ≠ 200`，18 个双行簇被放权 1.18 倍 |

> **对 D 的说明（避免误读你的原话）**：你写的是「抽中概率 `P(c)=m_c/200`，且每个 replicate 的原始行权重按抽样次数恢复」。
> 这两件事**同时做**时，比值式的权重变成 `m_c²`（上表 D 行），18 个双行簇会被系统性放权 —— 与「保留行权重」的目标相反。
> 若 `P(c) ∝ m_c` 但**不**恢复权重（直接平均抽到的簇均值），它在期望上确实是 200 行均值的无偏估计，
> 与 A 渐近等价。**两者都可辩护，我选 A**：行权重在代码里是显式的 `m_c`，且簇大小相等时精确退化为教科书 bootstrap，
> 便于审阅者一眼核对。

### 2.2 B 方案为什么必须否掉（本轮实测，不是推理）

我先实现的正是 B（分母固定 200），理由是「这样每个 replicate 的目标就是 `(1/200)Σ`」。
在 3 簇玩具数据（`a=[0], b=[0], c=[10,10]`）上它给出 `4.34`，而真值是 `5.00` —— 测试直接挂了。
换成比例式后是 `4.37`… 仍然不是 5.00，**两者都有偏**，但偏的原因不同：

| 现象 | 原因 | 是否致命 |
|---|---|---|
| B 的 bootstrap 均值偏 | 多出 `Var(Σk_c m_c)·μ²` 项 | **致命**：`d` 整体平移常数会让 SE 变 —— 任何方差估计量都不许可 |
| A 的 bootstrap 均值偏 `O(1/n_clusters)` | 比值估计量的有限样本偏倚（标准文献称 ratio/Hájek estimator 为 approximate unbiased，非严格无偏） | 可接受：**点估计本身精确**；但**不作「数值可忽略」的声称**，见 §2.4 |

于是在基线记录上量了一次（B=4000，同一 seed）：

| 实现 | point | replicate 均值 | `se` |
|---|---|---|---|
| B（分母固定） | −0.036000 | −0.036003 | **0.000758** |
| A（Hájek） | −0.036000 | −0.035998 | **0.000235** |

B 的 `se` 被放大了 **3.2 倍**（`DEFF_empirical` 从 0.88 涨到 >2.5，直接触发 `deff_empirical_implausible`）。
一个「看起来更严格」的实现，实际是给 SE 掺了一段与估计量水平成正比的伪方差。

⇒ 现已写成**测试** `test_translation_invariance`：把所有 `d_i` 加 5.0，`se` 必须逐位不变。B 方案过不了这条。

### 2.3 为什么这条值得单列一节

因为它不是笔误，而是**两种都像对的写法**，且错的那个方向让 `SE` 更大、看起来更保守。
如果不写下来，下一轮有人「顺手优化成分母固定」时，测试会挡；但挡不住有人把测试也一起改了。

**定性（西瓜先生 2026-11-25 23:20 裁定，不再重开）**：这是
**blocking statistical implementation bug，已修复；不是数值精度问题**。
判据不是「两种写法算出的数不同」，而是「B 方案在 `d_i → d_i + C` 下会改变 `SE`」——
一个含 level-dependent variance component 的估计量，即使数值上更保守，也不是同一个目标参数的方差估计。

### 2.4 冻结条款：`SE_cluster_w` 的定义至此关闭

**正式冻结**（同一裁定）：

```
SE_cluster_w = uniform-cluster bootstrap + Hájek row-weighted replicate statistic
```

即每个 replicate 取 `Σ_c k_c m_c ȳ_c / Σ_c k_c m_c`，`k_c` 为均匀抽簇计数。
「要不要恢复 `m_c` 权重」**不再是开放问题**：抽簇机制（uniform）与目标 estimand 的行权重（`m_c`）必须**分开定义**，
把两者混在一起会把 row-weighted target 悄悄变成另一种 cluster-weighted target（§2.1 表 D 行）。
`weight_by_size=False` 分支保留，只为测试能证明它与 A 是**两个不同参数**（§2.1 表 C 行，实测差 50%）。

**配套的措辞约束**（西瓜先生原话要求，写入证据链）：

> Hájek ratio bias is a methodological approximation; with 182 clusters it is expected to be small
> relative to the variance scale, but no numerical negligibility claim is used in the H2 decision.

落地为：`pilot.py::_bootstrap_core` docstring 已按此改写（原文「far below the resolution of anything here」删除），
`test_bootstrap_mean_tracks_point_at_the_real_cluster_count` 的 docstring 同步改为「1% 容差检查，非可忽略性声称」。
**这两处是纯注释改动，无一行逻辑变化**，`350 tests` 输出逐字节不变（§9 记录重跑结果）。

`test_translation_invariance` 保留为**硬测试**，地位等同门：它挡的不是精度，是估计量错位。

## 3. 新增三门（G15 / G16 / G17）

| 门 | 代码 | 检查 | 不通过 |
|---|---|---|---|
| **G15** | `INVALID_PAIRED_SOURCE` | 每个 `(estimand, seed)` 的 200 对上，**两臂的原始 `f1` 都在**，且 `input_sha256` / `gold_index` / `cluster_id` 一致；若记录里另存了 `d`，必须与 `f1_cand − f1_ref` 在 `1e-12` 内一致 | 阻断，不出统计 |
| **G16** | `REJECT_AUTHORITY_CLAIM` | `verdict_authority is False` **且** `purpose == "variance_estimation"` | 阻断 |
| **G17** | `REJECT_PILOT_SUPPLIED_DELTA` | 记录（含嵌套字典）里**不得**出现 `delta / delta_pp / ni_margin / margin_pp …` | 阻断 |

**G15 是 G6 的镜像**，这一点值得写清：

- `INVALID_SUMMARY_ONLY` 防的是「只有汇总值 ⇒ 算不出 `d_i`」；
- `INVALID_PAIRED_SOURCE` 防的是「有 `d_i`，但两臂原始 `f1` 已删/对不上 ⇒ 有均值有 CI，审计链断了」。

两者拦的是同一个病的两端：**任何重算路径上缺一环，记录就失效**。
所以 G15 不只检查「字段在不在」，还**复算**：`|stored_d − (f1_cand − f1_ref)| > 1e-12` 就算 FAIL。
`d` 一致时放行（有测试 `test_g15_stored_d_agreeing_is_accepted`）——存 `d` 是允许的，**只用 `d` 不允许**。

**G6 与 G15 必须保持两个独立门，不因「看起来重复」而合并**（西瓜先生 2026-11-25 23:20 裁定）：

| 门 | 区分的是 | 合并后会丢掉的判据 |
|---|---|---|
| G6 `INVALID_SUMMARY_ONLY` | 「有没有 `d` 字段」 | 记录层是否给了逐行配对分数 |
| G15 `INVALID_PAIRED_SOURCE` | 「`d` 是不是从两臂原始结果算出来的」 | 审计链是否可重算 |

一条只有 `d` 的记录同时触发的其实是两件事：**源不可追溯**（G15）与**重算路径缺失**（G6 的另一半语义）。
把两门压成一门，报告里就只剩一个 `code`，无法区分「数据本来没采」与「数据采了但 `f1` 被裁掉」——
这两种情形对上游的处置完全不同（前者改采集脚本，后者改导出逻辑）。
现实现里两门可同时出现在 `blocking` 列表，CLI 逐个打印，不选其一。

### 3.1 一个我差点漏掉的配对细节

`Δ_DCC` 的两臂 seed 不同：`C` 带构造 seed，`B′` 的 `seed` 是 `null`（R-d 的 `shared_side_deterministic: true`）。
若按 `(seed, arm, budget, row_id)` 直接查 `B′`，**每一对都会查不到**，然后被 G15 判成「配对缺失」——
看起来像数据缺了，实际是查表键写错。现在 `pair_rows` 对确定性臂一律用 `seed=None` 查，
确定性臂清单由 `meta.deterministic_arms` 声明（缺省 `("A_dense","B","B_prime")`），并写进报告，不静默推断。

## 4. `DEFF` 与诊断旗标

| 量 | 定义 | 角色 |
|---|---|---|
| `deff_empirical` | `(se_cluster_w / se_iid)²` | **实测**，唯一允许描述「膨胀多大」的量 |
| `deff_model` | `1 + 0.18·ρ_d` | **等方差模型内**的读数，仅用于比对 |
| `deff_bound` | `2.0` 通用 / `1.18` 模型内 | 上界，**不是估计** |

`|deff_empirical − deff_model| > 0.10` ⇒ `model_misfit = true`，**并且只加旗标**。
已写成测试 `TestModelMisfitIsOnlyADiagnostic`：把阈值在 `-1.0` 与 `1e9` 之间来回拨，
`model_misfit` 翻转，而 `se_cluster_w / ci_low / ci_high / mean_d / deff_empirical / deff_model` **逐位不变**。
另一条 `test_model_never_replaces_measured_se` 直接断言「模型反推的 SE ≠ 实测 SE」——
防止哪天有人用 `se_iid·√(1+0.18ρ)` 去顶替 `se_cluster_w`。

**主次关系（西瓜先生 2026-11-25 23:20 正式接受，写成不变量）**：

```
主判决   ←  仅  Δ̂ ,  SE_cluster_w ,  δ
诊断层   →  SE_iid / ρ_D / ρ_d / DEFF_model / DEFF_empirical
```

诊断层**只能解释「为什么这个 SE 是这个大小」，不能替代它**。
`model_misfit = true` 时允许做的唯一动作是**加旗标并在报告里写明模型与实测不符**；
不允许改 `SE_cluster_w`、不允许退回 `SE_model`、不允许因此重算 `CI`。
否则逻辑会退化成「模型不符合数据 ⇒ 换回模型认为应该有的 SE」，诊断意义归零。

### 4.1 `deff_empirical < 1` 是合法结果，但不是好消息

合成基线记录上 `ρ_d = −0.729`，于是 `deff_empirical = 0.88 < 1`。
这是**负的簇内相关**造成的，数学上没问题，但必须打旗标 `deff_empirical_below_one`：
`DEFF < 1` 不得被读成「方差变小了，赚了」，也不得据此声称存在聚类效应。

**但它同样不得被读成「实现错了」**（西瓜先生 2026-11-25 23:20）：
聚类稳健方差**不要求**设计效应必然大于 1；负的簇内相关或其他依赖结构确实可以让聚类设计方差
小于独立观测基准。因此 `deff_empirical_below_one` 只是 `flags` 里的一条**标记**，
不进 `blocking`、不改 `se_cluster_w`、不改判决。真正需要拦的是「`DEFF` 掉到 1 以下就回头微调权重」
——那等于用结果去反推估计量，本门链里没有任何路径允许这么做。
（设计里「`DEFF` 的 bootstrap 区间包含 1 则不得声称聚类效应」需要 `DEFF` 自身的区间，本轮**没有**实现
`DEFF` 的区间 —— 只实现了 `SE` 的嵌套区间。这条缺口写在 §5。）

### 4.2 合成数据顺手实证了 `ρ_D ≠ ρ_d`

基线记录上 **`ρ_D = 0.98`，`ρ_d = −0.73`**。同一个「同输入 + greedy」结构，分数几乎完全相关，
而**配对差**却负相关。如果按 `ρ_D` 去算 `DEFF`，会得 `1 + 0.18×0.98 = 1.18`；实测是 `0.88`。
**方向相反、量级差 34%**。这条不是新发现，是 `design/22` §3.5 那个区分的合流证据，已写成
`test_rho_d_and_rho_D_are_not_interchangeable`。

> ⚠️ 必须标明：这是**我构造的合成记录**的性质，不是 narrativeqa 的读数。
> 真实数据上 `ρ_d` 可能为正也可能接近 0，**未测**。

**保留条款（西瓜先生 2026-11-25 23:20）**：`ρ_D = 0.98` / `ρ_d = −0.73` 这一对数值
**永久保留在测试套件里，作为 validator 的反例证据**，用途仅有一条：
证明 `ρ_D > 0` 而 `ρ_d < 0` 时，拿 `ρ_D` 代 `ρ_d` 会把 `DEFF` 的**方向**算反（不是「近似一点」）。
它**不得**以任何形式进入 narrativeqa 的真实数据先验、δ 推导、或 pilot 元数据默认值。
对应测试 `test_rho_d_and_rho_D_are_not_interchangeable` 的 docstring 必须带
`synthetic construction; not a narrativeqa reading` 字样。

## 6. 敏感性分带：三个名字，四条带

`design/23` §3 给了三个状态名。实现里保持这三个名字不变，另加 `sensitivity_detail` 记录落在哪条带：

| `sd_d_row`（pp） | 状态 | `detail` |
|---|---|---|
| `< 12.117` | `unconditional` | 即使 `DEFF=2` 也成立 |
| `[12.117, 15.775)` | `model_dependent` | `band [universal, model)` |
| `[15.775, 17.1365)` | `model_dependent` | `band [model, row)` |
| `>= 17.1365` | `beyond` | 任何方差结构都判不出 |

阈值**不硬编码**：`sigma_gate_pp(mean_pp, delta_pp, deff)` 由 `mean`、`δ` 现算，
`design/22` 那三个数只是 `mean=−3.875, δ=1.5` 的特例（测试锁住了这个等价性）。
这样一旦某个 pilot 的 `mean_d` 不是 −3.875，分带跟着数据走，不会拿着旧常数去套新记录。

## 7. `se_cluster_w_ci`：SE 自己的区间

`design/23` §3 要求「`SE` 自身也是估计量，必须给区间」。实现是**嵌套 bootstrap**：
外层抽簇 → 内层再抽 → 得 `se*` 分布 → 取 2.5/97.5 分位。

| 项 | 值 |
|---|---|
| 库默认 | `se_ci=(0,0)` 关闭（测试要快）；此时记录打旗 `se_ci_missing`，**不静默省略** |
| CLI 默认 | `outer=60, inner=100`，记录带 `ci_method="nested_bootstrap(outer=60,inner=100)"` |
| 代价 | B=2000 时整条 CLI 跑 **1.7 s**；B=10000 约 7 s |

⇒ 这是**二阶读数**，只用来判断「`SE` 自己稳不稳」，不进判决链。
