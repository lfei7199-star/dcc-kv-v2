## 0. 一句话

**pilot 的唯一合法用途是估计方差**，所以它的产物必须让「逐行 `d_i` → `SE_cluster` → `CI` → 三态判决」这条链**能从原始数据完整重算**；
任何只能从汇总表反推的量，视为记录无效。
**`ρ_d` 不再是判决输入**——它降级为「解释方差为什么膨胀」的诊断量（`design/22` §3.4.3）。

## 1. 两个 pilot 不是一个 pilot（先分开，否则会白跑）

| pilot | 目的 | 需要的重复 | 最小规模 |
|---|---|---|---|
| **P-σ** | 估 `σ_D`、`ρ_D`、`ρ_d`、`DEFF` | **单 seed 就够**（行间变异本身就是信息源） | 200 行 × 必要臂 × 必要预算 |
| **P-seed** | 估 `σ_s`（新管线的 seed 层 sd） | **K = 30 个 seed** | 每 seed 一次完整评测 |

- `σ_D` **不需要** 30 个 seed。拿 30 seed 去估行级 `σ_D` 是浪费，而且若每 seed 只有部分行，反而更差。
- `σ_s` **必须** 30 seed，且**必须**由新实现（`sample_pool`/`split_pool`）产生。
- 两者可以跑在同一批计算里，但**记录必须分开标记**（§6 `purpose` 字段），不得混记。

⇒ 一个容易犯的错：把 30 seed 的结果**先平均再算 `σ_D`**。这会把 seed 变异混进行间变异里，`σ_D` 同时污染了两个量。
**`σ_D` / `ρ_d` 必须逐 seed 算，再报告其分散度**；合并的只有最终点估计。

### 1.1 字段命名：不许出现无量纲的「`sigma_D`」

**这是本轮新增的硬约束**（西瓜先生 22:51）。`σ_D` 在不同语境下指两个不同的东西，
一个裸名会让后来人（包括我自己）分不清：

| 字段名 | 定义 | 含义边界 |
|---|---|---|
| **`sigma_D_by_seed[s]`** | `SD(d_{s,1..200})`，第 `s` 个 seed 内的**行间离散** | **只代表该 seed 条件下的行间离散**，不得称「`Δ` 的标准差」 |
| **`sigma_D_median`** / `sigma_D_range` | 30 个 `sigma_D_by_seed` 的中位数与极差 | 跨 seed 稳定性 |
| **`sigma_s`** | `SD(\bar d_1, …, \bar d_30)` | seed 层离散（构造随机性） |
| ❌ `sigma_D` | —— | **禁止使用**：无条件下标的同名量会被误读成总体量 |

⇒ 报告模板里写「`σ_D`」一律视为不完整，必须带 `_by_seed` 或 `_median`。
⇒ `sigma_s` 与 `sigma_D_by_seed` **不可互相替代**：前者问「换 seed 会不会变」，后者问「换 prompt 会不会变」。

## 2. 逐行记录 schema（唯一权威来源）

格式：`jsonl`，一行一条「行 × 臂 × 预算 × seed」的评分单元。纯文本，不引入二进制列存（与现有记录一致）。

### 2.1 必填字段

| 字段 | 类型 | 取值域 / 约束 | 为什么必须有 |
|---|---|---|---|
| `row_id` | int | `0..199`，等于 `longbench_qa.jsonl` 的行序 | 配对与重采样的唯一行标识；**不得用 `id`（200 个不同哈希，无法聚簇）** |
| `cluster_id` | str | `input_sha256` 的**前 16 位十六进制**（规则见 §2.1.1） | 聚簇键。**可由原始数据复算**，不接受人工指定 |
| `cluster_size` | int | `1` 或 `2` | 冗余校验用（应为 164 个 1、18 个 2） |
| `input_sha256` | str | 模型输入的**规范化后** sha256（完整 64 位） | 验证「簇内同输入」这个前提本身；也是 `cluster_id` 的来源 |
| `gold_index` | int | 簇内序号 `0` / `1` | 区分同簇两行的 gold（这是 `ρ` 不为 1 的唯一来源） |
| `arm` | enum | `A_dense` / `B` / `B_prime` / `C` | 归因三边 |
| `budget_t` | int\|null | `819` / `1637` / `3274` / `6548`；`A_dense` 为 `null` | Q10 与四档 sweep 的预算键 |
| `seed` | int\|null | 确定性臂为 `null`；`C` 为其构造 seed | `σ_s` 与可复现性检查 |
| `f1` | float | **`[0, 1]` 原始值** | 见 §2.2 值域纪律 |
| `pred_sha256` | str | 预测文本 sha256 | 验证 greedy 假设（§5 G4） |
| `pred_len` | int | ≥0 | 诊断截断/退化输出 |
| `truncated` | bool | —— | 长度因子两态 |
| `effective_len` | int | 实际喂入 token 数 | 与 `L` 档位区分（`design/22` §5.1） |

### 2.1.1 哈希的序列化规则（必须先固化，再算哈希）

我原来写的 `sha256(context + question)[:16]` 有**字段边界歧义**：`("ab","c")` 与 `("a","bc")` 拼出来同一串。
这类错不会报错，只会让两行被错并成一簇（或该并的没并）。**规则定死如下**：

1. **Unicode 规范化**：两个字段各自先做 `unicodedata.normalize("NFKC", …)`。
   ⇒ 否则全角/半角、合成字符的差异会造成「同一输入算出不同哈希」。
2. **编码**：UTF-8，`errors="strict"`（不允许替换字符，出现即 FAIL）。
3. **换行统一**：`\r\n` 与 `\r` 一律先转 `\n`；字段内部的换行**保留**（context 是多行的，不能压成一行）。
4. **长度前缀序列化**（消除边界歧义）：
   ```
   payload = b"pilot-input/v1" + b"\x00" \
           + len(ctx_bytes).to_bytes(8,"big")  + ctx_bytes \
           + len(q_bytes).to_bytes(8,"big")    + q_bytes
   input_sha256 = sha256(payload).hexdigest()          # 64 hex
   cluster_id   = input_sha256[:16]                    # 16 hex
   ```
   ⇒ 域分隔符 `\x00` 只是可读性冗余，**真正消除歧义的是 8 字节大端长度前缀**。
5. **短 ID 碰撞检查**（必须执行，不能假设）：
   - 对全部 182 个 `input_sha256` 取前 16 位，**若不同完整哈希映射到同一 `cluster_id` ⇒ FAIL**；
   - 实际碰撞概率约 `182²/2 / 16^16 ≈ 6×10⁻¹⁶`，但**必须检查而不是论证**——因为这是记录正确性的门，不是概率问题。
6. **版本绑定**：序列化规则带 `v1` 前缀。**改规则必须改前缀 + 升 `schema_version`**，
   否则旧记录会被静默重算成不同的簇。

> 为什么不直接用 token id 序列：tokenizer 版本一变，同一文本的 id 就变，`cluster_id` 随之漂移。
> 用规范化文本 + 长度前缀，至少与 tokenizer 解耦。**但要在记录里注明 tokenizer 身份**（§2.3）。

### 2.1.2 记录的唯一索引

**唯一的行级主键是 `(seed, arm, estimand_proxy, row_id)`**——但 `estimand` 不是独立字段，
它是**由两条臂的配对差派生**的。所以落盘的主键是：

```
唯一键 = (seed, arm, budget_t, row_id)
```

约束（validator 必查）：

| 约束 | 内容 |
|---|---|
| **U1** | 同一 `(seed, arm, budget_t)` 单元内，`row_id` 覆盖 `0..199` 各一次，**无缺无重** |
| **U2** | `Δ_shared` 必须由 `(B′, B)` 在同一 `(seed, budget_t, row_id)` 上配对，**不得共用一个差值列** |
| **U3** | `Δ_DCC` 必须由 `(C, B′)` 同样配对，**与 `Δ_shared` 各自独立成列、独立方差字段** |
| **U4** | `d_i^{shared}` 与 `d_i^{DCC}` 是**两个变量**，`Var`、`sd`、`ρ_d`、`SE` 全部**分开存**，不得共享字段 |

⇒ 这一条是防「两条 estimand 共用一个 `sd_d` 字段」——那样一旦有人改了配对方式，两个判决会同时错，且看不出来。

### 2.2 `f1` 一律存 `[0,1]`，不存 pp

- 存 `[0,1]`，`pp` 只在**派生层**做 `×100`（与 `design/19` §1 的 `f_d(q) = 100q` 一致）；
- 若原始 evaluator 直接给百分数，**必须除以 100 后再落盘**，并在 `evaluator.raw_scale` 注明；
- 越界（`<0` 或 `>1`）⇒ **FAIL**，不做 clip（与 `f_d` 的值域断言同一纪律：禁截断、禁重标定）。

> 理由：一旦允许「有的行存 pp、有的存比例」，后面所有差值与 `δ` 的单位都不可信，且这种错**不会报错**，只会让 `Δ` 大 100 倍。

### 2.3 必须随记录一起落盘的元数据（每文件一份，不是每行）

| 字段 | 内容 |
|---|---|
| `dataset` | `zai-org/LongBench@5e628be4` / `narrativeqa` / `test` |
| `dataset_sha256` | `longbench_qa.jsonl` 的 `896a04a0…` |
| `n_rows` / `n_clusters` | `200` / `182` |
| `evaluator.name` / `.version` / `.raw_scale` | F1 实现身份与量纲 |

### 2.4 `schema_version`（本轮新增）

| 项 | 规则 |
|---|---|
| 字段 | 每条记录必带 `schema_version`；初始 **`pilot-1`** |
| 升级条件 | **字段增删、含义变更、哈希序列化变更、配对方式变更 ⇒ 必须升版本** |
| 禁止 | 在旧版本号下改含义；「历史上就是这么写的」不是理由 |
| 兼容 | validator 按记录自带 `schema_version` 选规则；**未知版本 ⇒ 拒收**，不做「尽力解析」 |
| 冻结 | 版本号 + 字段表 + 序列化规则一起写入 prereg（`design/22` §7 第 24 项） |

> 理由：这个项目已经因为「同一个数字在不同文档里含义不同」返工好几轮（`1.5` / `8.63%` / `182` / `182 vs 200`）。
> 版本号是最便宜的止损手段。

## 3. 派生记录 schema（由 §2 重算得到，**不得手写**）

每个「估计量 × 预算（对）」一条。**注意角色分级**（`design/22` §3.4.3）：

| 角色 | 字段 | 计算式 | 备注 |
|---|---|---|---|
| **主（判决用）** | **`se_cluster_w`** | 簇级 bootstrap，\(\Pr(c)\propto m_c\)，`B ≥ 10000` | **唯一进入 CI 与判决的标准误** |
| **主** | `ci_low` / `ci_high` | `mean_d ± 1.96·se_cluster_w` | 判决用这一套 |
| 主 | `se_cluster_w_ci` | bootstrap 分布的 2.5/97.5 分位 | `SE` 自身也是估计量，必须给区间；未算则打旗 `se_ci_missing`（不静默省略） |
| 诊断 | `mean_d` | `mean(d_i)` | 保留全精度（`−3.875000` 那类），显示两位 |
| 诊断 | `sd_d_row` | `sd(d_i, ddof=1)` | 字段名**不得**叫裸 `sigma_D`（§1.1） |
| 诊断 | `se_iid` | `sd_d_row/√200` | 独立假设基准 |
| 诊断 | **`deff_empirical`** | `se_cluster_w² / se_iid²` | **实测的方差膨胀**，期望 `[1, 2]` |
| 诊断 | `deff_model` | `1 + 0.18·rho_d.point` | **等方差模型内**的读数，与 `deff_empirical` 比对 |
| 诊断 | `deff_bound_universal` | **`2.0`**（常数） | 通用上界，不是估计 |
| 诊断旗标 | `deff_empirical_below_one` | `deff_empirical < 1` 时必打 | `ρ_d < 0` 时合法，但**不得**读成「方差变小」或据此声称聚类效应 |
| 诊断旗标 | `model_misfit` | `abs(deff_empirical − deff_model) > 0.10` | 只加旗标；**禁止**改 `se_cluster_w`、禁止回退到 `deff_model` |
| 诊断 | `rho_D` | `{method, point, ci_low, ci_high, ci_method, n_pairs}` | **仅诊断**，不进方差 |
| 诊断 | `rho_d` | 同上 | 解释膨胀来源；**不再承担判决** |
| 诊断 | `sensitivity_state` | `unconditional` / `model_dependent` / `beyond` | 依 `design/22` §4.5 三层：`sd_d_row` vs `12.117` / `15.775` / `17.1365` |
| 派生 | `n_rows` / `n_clusters` / `n_pairs` | `200` / `182` / **`18`** | `n_pairs` 是 `ρ` 的全部信息量 |
| 派生 | `verdict` | 依 `design/22` §4.1 三态，用 `ci_low/ci_high`（即 `se_cluster_w` 那套） | **重算得出**，不采信输入 |

⇒ **`verdict` 必须由 `fold` 式函数从 `mean_d` + `ci_*` + 冻结 `δ` 重算并比对**——与 `envelope.fold_verdict` 同一纪律：写进记录的判决若与重算不符，视为篡改。
⇒ **禁止**用 `deff_model`（`1+0.18ρ_d`）替代 `se_cluster_w` 去算判决 CI。它在表里是**诊断行**，不是计算路径。
⇒ 若 `deff_empirical` 与 `deff_model` 相差 > 0.10，记录里必须标 `model_misfit = true`，并在报告注明
「等方差/共同相关模型不成立，以 `deff_empirical` 为准」（`design/22` §3.4.3）。

## 4. `ρ` 的估计：方法与区间（两个都要报）

`ρ` 的识别信息**全部来自 18 个双行簇**（164 个单行簇对 `ρ` 零信息）。所以：

| 项 | 要求 |
|---|---|
| 方法（至少两种） | ① **Fisher-z 区间**（`SE = 1/√(n_pairs−3) = 0.258`）；② **簇级 bootstrap 区间**（重采样 18 个双行簇，`B ≥ 10000`） |
| 点估计 | 逐对 Pearson；若用方差分解（`ρ̂ = (MSB−MSW)/(MSB+MSW)`，`m=2`）须在 `method` 里写明 |
| 必须记录 | `method` / `point` / `ci_low` / `ci_high` / `ci_method` / `n_pairs` / `bootstrap_B` / `bootstrap_seed` —— **缺任一项视为记录不完整** |
| 诚实标注 | Fisher-z 假设二元正态，而 F1 是 `[0,1]` 有界、零膨胀 ⇒ **必须**标注「正态性可疑，以 bootstrap 区间为主，Fisher-z 作对照」 |
| 区间失配处理 | 两法区间若相差 > 0.15，**不得**取均值或择优；应报两个区间并注明「`ρ` 未能稳定识别」 |

`ρ_D` 与 `ρ_d` **各自独立估计**，不得用 `ρ_D` 代替 `ρ_d`（`design/22` §3.5）。
`Δ_shared` 用 `ρ_d(B′−B)`，`Δ_DCC` 用 `ρ_d(C−B′)`，两条不得互借。

> ⚠️ **适用边界（西瓜先生 22:51 强调）**：上述两种区间**只限「18 个双行簇的相关系数区间」**。
> 它们**不是** 182 簇的均值 CI——重采样单位（18 vs 182）、目标参数（`ρ` vs `μ`）、
> 采样分布（有界相关 vs 近似正态均值）三者都不同。
> ⇒ 记录里两套区间的字段必须分开命名（`rho_d.ci_low` vs `ci_low`），**禁止共用 `ci_low`**。
> ⇒ 引用时写「`ρ_d` 的 95% 区间（Fisher-z / 簇 bootstrap）」，
> **不得**写「95% CI」，否则会被读成均值区间。

## 5. 完整性门（缺一即降级，不补默认值）

| 门 | 检查 | 不通过时 |
|---|---|---|
| **G1** | 每个 (arm, budget, seed) 单元恰 200 行，`row_id` 覆盖 `0..199` 无缺无重 | `BLOCKED_MISSING_ROWS` |
| **G2** | `cluster_id` 恰 182 个不同值，`cluster_size` 分布恰 `{1:164, 2:18}` | `BLOCKED_CLUSTER_MISMATCH` |
| **G3** | `cluster_size=2` 的两行 `input_sha256` 相同、`gold_index` 为 `{0,1}` | `BLOCKED_INPUT_MISMATCH`（簇定义被破坏） |
| **G4** | 同簇同臂的 `pred_sha256` 相同（greedy 下应如此） | `WARN_PRED_DIVERGENCE`（**不阻断**，但必须解释；若真的不同，`ρ` 的前提要重审） |
| **G5** | `rho_D` / `rho_d` 的七项齐全 | `INCOMPLETE_RHO` |
| **G6** | 存在逐行记录（不是只有汇总值） | **`INVALID_SUMMARY_ONLY`** —— 这是本文档存在的主要理由 |
| **G7** | `f1 ∈ [0,1]` 全部行；元数据 `raw_scale` 与落盘量纲一致 | `FAIL_SCALE` |
| **G8** | `construction.randomness_source = calibration_query_subsample`；无 `rademacher` | `REJECT_LEGACY_PROVENANCE` |
| **G9** | `cluster_id = input_sha256[:16]` 对**每一行**自洽；且 182 个短 ID **两两不同** | `FAIL_CLUSTER_HASH`（§2.1.1 第 5 条） |
| **G10** | `cluster_serialization` 字段存在且为已知版本；未知版本 ⇒ 拒收 | `REJECT_UNKNOWN_SERIALIZATION` |
| **G11** | 唯一键 `(seed, arm, budget_t, row_id)` 无重；每个完整单元 200 行 | `FAIL_ROW_INDEX`（U1） |
| **G12** | `Δ_shared` 与 `Δ_DCC` 的 `d_i` 列、`var`、`sd`、`rho_d`、`se` **字段各自独立** | `FAIL_ESTIMAND_CONFLATION`（U2–U4） |
| **G13** | 逐 seed 的 `sigma_D_by_seed[s]` 与 `rho_d_by_seed[s]` 齐全；**无裸 `sigma_D` 字段** | `FAIL_UNCONDITIONAL_SIGMA`（§1.1） |
| **G14** | `schema_version` 存在且已知 | `REJECT_UNKNOWN_SCHEMA` |
| **G15** | 每个 `(estimand, seed)` 的 200 对上**两臂原始 `f1` 都在**，且 `input_sha256` / `gold_index` / `cluster_id` 一致；若另存了 `d`，须与 `f1_cand − f1_ref` 在 `1e-12` 内一致 | **`INVALID_PAIRED_SOURCE`**（G6 的镜像：有 `d_i` 但审计链断） |
| **G16** | `verdict_authority is False` **且** `purpose == "variance_estimation"` | `REJECT_AUTHORITY_CLAIM` |
| **G17** | 记录（含嵌套字典）里不得出现 `delta / delta_pp / ni_margin / margin_pp …` | `REJECT_PILOT_SUPPLIED_DELTA` |

> G15 与 G6 拦的是同一个病的两端：**任何重算路径上缺一环，记录就失效**。
> 只存 `d_i` 而删掉两臂 `f1`，能算均值也能算 CI，但复算不了 —— 这正是 `INVALID_PAIRED_SOURCE`。
> 存 `d` 本身是允许的，**只用 `d`** 不允许。详见 `design/24` §3。

> G6 的口径：**「从汇总表反推 DEFF」一律无效。** 汇总表里没有 `d_i`，就没有 `ρ_d`，就没有 DEFF，
> 也就算不出 `design/22` §3.6 的各层门槛。这不是洁癖——`design/22` §4.4 那个被封掉的
> 「跨档 sd = 0.6767 当 σ」正是**只有汇总值**时才诱人的算法。

## 6. 记录上的判决权限（防 pilot 读数被当正式结果）

| 字段 | 值 | 含义 |
|---|---|---|
| `purpose` | `variance_estimation` | 本次跑是为了测 σ，不是判定 |
| `verdict_authority` | **`false`** | 记录里任何 `verdict` 字段都**不得**被引用为试验结论 |
| `may_not_be_cited_as` | `["NI_PASS", "NI_REJECTED", "H2 判决", "质量主张"]` | 白名单式拦截 |

⇒ 与「CPU 记录不得拿硬件 PASS」同一纪律：**pilot 的 σ 可以用来定 δ，但不能用来说 H2 通过或失败。**
⇒ 若 pilot 点估计落在界外，只能写「pilot 观测到 `mean_d = …`，该值不构成判决」，**不得**写「已判负」。

## 7. 从原始数据到三态判决的重算路径（必须能一步跑通）

```
§2 逐行 f1 + cluster_id + gold_index + seed
  → 逐 seed 配对差 d_{s,i}（Δ_shared 与 Δ_DCC 各一套，不共用列）
  → 逐 seed：mean_d_s, sd_d_row_s, rho_d_s      → sigma_D_by_seed / rho_d_by_seed
  → 跨 seed：mean_d 的 seed 层 sd（= sigma_s）
  → 簇级 bootstrap（Pr(c) ∝ m_c）→ se_cluster_w + 其 2.5/97.5 分位
  → 诊断：se_iid, deff_empirical = se_cluster_w²/se_iid², deff_model = 1+0.18·rho_d
  → sensitivity_state（§4.5 三层：sd_d_row vs 12.117 / 15.775 / 17.1365）
  → verdict（§4.1 三态，用 se_cluster_w 那套 CI，δ 由 prereg 提供）
```

⇒ **判决链只依赖 `mean_d` + `se_cluster_w` + 冻结 `δ`**；`ρ_d` / `deff_model` 在链外（诊断分支）。
⇒ 三次重算结果必须逐位一致（同一输入 → 同一输出），否则视为记录不稳定。
⇒ 若 `δ` 未冻结 ⇒ 链在最后一步停住，`verdict = NOT_TESTABLE`，**不得**用先验 δ 顶替。
